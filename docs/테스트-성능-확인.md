# 백엔드 API 테스트·성능 확인 (2026-11-07)

백엔드 API 13개를 Postman 컬렉션으로 한 번에 돌려 상태 코드와 응답 시간을 확인한 기록입니다. 기준은 `docs/API.md` 입니다.

## 1. 확인 방법
- 컬렉션 파일: `docs/postman/capstone-api-check.postman_collection.json` (Postman 의 Import 로 가져옵니다)
- 백엔드를 `localhost:8080` 에서 켜 두고 컬렉션의 Run 으로 실행합니다.
- 요청마다 테스트 두 개가 붙어 있습니다: 상태가 200 인가, 응답이 1초 이내인가.
- 첫 실행은 느릴 수 있어서 두 번째 이후 값을 기준으로 봅니다.

## 2. 결과 (재수집 전, 진행 중 공고 약 4,200건 기준)
5회 실행 모두 13개 요청이 200 이고 테스트 26개가 모두 통과했습니다. 응답 시간 평균은 약 81ms 입니다.

| 요청 | 응답 시간 |
|---|---|
| GET /api/health, /api/health/db | 3~9ms |
| GET /api/skills?q=spr&limit=20 | 5~11ms |
| GET /api/summary | 17~23ms |
| GET /api/jobs/1/skills?limit=5 | 9~38ms |
| GET /api/trends/matrix?jobIds=1,23,35&limit=6 | 8~42ms |
| GET /api/trends/job-demand | 44~78ms |
| GET /api/trends/combinations?jobId=1&limit=5 | 69~99ms |
| GET /api/jobs | 92~110ms |
| POST /api/analysis | 7~71ms (첫 실행만 71ms) |
| GET /api/postings?jobIds=1&page=1&size=15 | 81~88ms |
| GET /api/postings/{id}?mySkills=… (상세) | 10~57ms (첫 실행만 57ms) |
| GET /api/postings?sort=matching&mySkills=Java,Spring,MySQL,Docker,AWS (맞춤 정렬) | 415~431ms |

맞춤 정렬은 공고마다 일치율을 계산하는 방식이라 가장 느립니다. 이 값이 재수집 전 기준값입니다.
쪽이 뒤로 가는 경우(jobIds=1, page=50)도 약 300ms 로 비슷했습니다.

## 3. 오류 응답 확인
공고 목록·상세의 오류 응답이 `API.md` 의 오류 표와 같은지 확인했습니다. 모든 오류는 `status`, `code`, `message` 세 칸의 같은 모양입니다.

| 요청 | 결과 |
|---|---|
| sort=matching 인데 mySkills 없음 | 400 MY_SKILLS_REQUIRED |
| page=abc | 400 INVALID_PARAMETER |
| jobIds=99999 | 404 JOB_NOT_FOUND |
| 없는 공고 번호 (/api/postings/1) | 404 POSTING_NOT_FOUND |
| size=51 | 400 INVALID_SIZE |
